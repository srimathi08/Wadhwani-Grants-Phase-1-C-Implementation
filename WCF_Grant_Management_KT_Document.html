1. Executive Overview & Solution Architecture

The WCF Grant Management System is an end-to-end platform automating multi-million dollar grant disbursements. It supports dynamic applicant intakes across three funding tracks (Job Fulfillment, Job Creation, Livelihood Upliftment), two-tier evaluation (Quantitative Validator Screening & Qualitative Multi-Reviewer Scoring), Executive Grant Committee deliberations (Accept / Reject), and automated compliance onboarding.

2. Record Types & Persona Role-Based Access Control (RBAC)

Access control is managed through RecordTypeHelper.cls and Account-level role flags. Unauthorized access is prevented via server-side assertions in WCFPortalUserController.assertRole().

3. End-to-End Lifecycle State Machine

1

Draft Creation & Intake

Applicant fills dynamic 28-question RFI (wcfDynamicForm). Draft auto-saves on blur. Initial draft save triggers Draft_Saved email notification.

2

Submission & Validator Screening (10-Day SLA)

Submission sets Submission_Round__c = 1. Alerts Validator queue (New_Application_Validator_Queue) and Applicant (Application_Received). Validator performs quantitative screening in wcfValidatorForm.

3

Reviewer Qualitative Evaluation (10-Day SLA)

When Validator passes screening (Validated__c = true), application moves to Under Review. Reviewer scores 22 criteria across 7 categories using wcfProposalReviewForm powered by WCF_ReviewFormJFController.cls. Assigned reviewer receives in-flow email New_Evaluation_Assinged.

4

Executive Committee Deliberation (Accept / Reject)

When review is submitted, Approver receives in-flow alert Approver_ReadyForDecision. Committee records one of 2 decisions: Accept or Reject in wcfApproverContainer. Decision dispatches Application_Approved or Application_Decision_Declined.

5

Compliance Onboarding

Applicant uploads mandatory certificates (80G, 12A, FCRA, MoU) in wcfComplianceDocs. When all reach Validated, WCFComplianceDocumentTrigger automatically flips status to Onboarded.

Deep Dive: WCFFormController.cls (Intake Architecture Backbone)

WCFFormController.cls (2,160 lines) is the foundational backend controller powering the dynamic RFI applicant intake experience across all grant tracks:

  • Active Funding Opportunity Discovery (getActiveFundingOpportunityId): Automatically detects and binds applications to the active FundingOpportunity record.
  • Real-Time AI Narrative Coaching Feedback (upsertAIFeedback, getAIFeedbackRecord, getFieldFeedback): Dynamically manages applicant coaching feedback stored in AI_Feedback__c across legal, sustainability, funding, synergies, job creation, and skilling.
  • Dynamic Multi-Lingual Picklist Resolution (getPicklistValuesForField): Inspects SObject field describes and metadata translations to dynamically render picklists in English, French, Portuguese, and Hindi.
  • Multi-Object Draft & Submission Engine (saveWCFDraftApplication, submitWCFApplication): Ingests structured JSON payloads and orchestrates transactional writes across IndividualApplication and all 8 core child entities.
  • Draft Reconstitution (getDraftWCFApplication): Rebuilds the complete WCFDraftWrapper data graph upon portal reload, restoring multi-year financial statements, outcome metrics, and uploaded files.
  • RFI Revision Persistence (saveRfiResponse): Updates specifically flagged fields when an applicant responds to revision requests from wcfRfiResponsePage.
  • Granular File Cell Mapping & Validation (getOutcomeFilesByCell, setFileCellKey, getApplicationAttachments, deleteUploadedFile, validateUploadedFile): Manages cell-specific attachment mappings for placement verification reports (Q24) and financial audits (Q28).
  • Applicant Progress Snapshot (getApplicationStatusForUser): Returns stage completion flags, submission round numbers, and pending action items for the logged-in user.

7. Apex Triggers & Handlers (Active Architecture Only)

Only 2 active triggers are used in the core WCF grant management process. All unused legacy triggers have been excluded from the active architecture.

7.1. ApplicationReviewTrigger (on ApplicationReview)

Events: before insert, before update, after insert, after update
Handler: ApplicationReviewHandler.cls

  • Consolidated Return Comments: Calls ApplicationReviewHandler.populateConsolidatedComments() to compile feedback from Question_Number_1__c through 28 into Consolidated_Return_Comments__c.
  • 10-Day SLA Working Days Calculation: When Validator marks Validated, sets Validator_Submission_Date__c = Date.today() and computes DueDate = addWorkingDays(Date.today(), 10) (excluding weekends).
  • Reviewer Stamping & Completion: Automatically stamps WG_Reviewer_Name__c = UserInfo.getName() and sets Due_Date_For_Approver__c = addWorkingDays(Date.today(), 10) upon submission.
  • Status Synchronization:
    • Validator Decision Return ➔ Sets IndividualApplication.Status = 'Revision Requested'.
    • Validator Decision Pass ➔ Sets IndividualApplication.Validated__c = true.
    • Validator Decision Flag ➔ Sets IndividualApplication.Flagged__c = true.

7.2. WCFComplianceDocumentTrigger (on WCF_Compliance_Document__c)

Events: after insert, after update
Handler: WCFComplianceDocumentTriggerHandler.cls

  • Monitors status updates across compliance records.
  • Calls WCFComplianceDocumentTriggerHandler.syncOnboardedStatus().
  • Invokes WCFComplianceController.computeOnboardingStage() to verify all required certificates for the organization's geography (80G, 12A, FCRA, Audited Financials, MoU).
  • When all mandatory documents reach Status__c = 'Validated', automatically transitions IndividualApplication.Status = 'Onboarded'.

12. Admin Guide & Troubleshooting Manual

12.1. Managing User Roles

To grant or revoke portal access for a user:

  1. Navigate to the user's Person Account record in Salesforce Lightning.
  2. Toggle the appropriate role checkbox:
    • WCFs_Validator__c = true ➔ Grants Validator screening access.
    • WCF_Reviewer__c = true ➔ Grants Reviewer evaluation access.
    • WCF_Approver__c = true ➔ Grants Approver committee deliberation access.
  3. WCFDashboardAccessController.cls dynamically evaluates these flags on the user's next session login.

12.2. Common Troubleshooting Solutions

Symptom Likely Cause Resolution
Applicant cannot edit returned application Proposal Status is not set to Revision Requested Verify ApplicationReview.Decision_Final_Decision_from_Sec_1_2__c = 'Return' and status is updated.
Proposal does not advance to Onboarded Not all mandatory compliance items are marked Validated Inspect wcfComplianceDocuments and ensure all required geography certificates have Status__c = 'Validated'.
Reviewer cannot see assigned proposal Missing Account role flag or Contact mismatch Ensure Account.WCF_Reviewer__c = true and ApplicationReview.Contact__c matches the reviewer.
Approver cannot record decision Decision comment or rejection reasons not filled When rejecting, select at least one rejection reason tile and provide decision comments.
